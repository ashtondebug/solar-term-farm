# 真实继电器故障注入

> 目标：验证“控制信号或继电器线圈失效时，泵是否安全停止”，以及“设备是否能检测到故障”。
>
> **当前结论：硬件没有继电器辅助触点或电流反馈，软件只能看到 GPIO 输出状态，不能确认触点是否真正闭合。** 因此本测试会暴露一个硬件缺口，而不是靠软件假故障掩盖。

## 1. 测试前条件

- 使用**低压直流泵**，不要接市电；
- 泵电源与主控电源分开，共地可靠；
- 继电器使用 COM/NO 常开触点；
- 继电器 IN 有 10kΩ 下拉；
- 泵和继电器线圈有续流二极管；
- 测试人员全程在场，手边有急停/断电方式；
- 先做空载继电器测试，再接水泵。

## 2. 测试脚本

设备在线时（同一局域网）：

```powershell
python tools\relay_fault_test.py \
  --base-url http://<device-ip> \
  --confirm RUN_RELAY_FAULT_TEST
```

脚本会启动一个短泵周期，然后提示你物理断开：

- **A**：继电器 IN 信号线（GPIO5 → IN）
- **B**：继电器线圈 VCC/GND

脚本只记录 API 返回值；不会伪造 `relay.fault`。

## 3. 验收矩阵

| 注入点 | 预期电气行为 | 当前固件能否检测 | 说明 |
|---|---|---|---|
| 拔掉继电器 IN | 线圈失电，NO 断开，泵停止 | **否** | GPIO 仍输出 HIGH，API 仍可能显示 pump=on |
| 拔掉线圈 VCC | 线圈失电，NO 断开，泵停止 | **否** | 依赖继电器无源释放 |
| 强制触点粘连 | 泵可能继续运行 | **否** | 最危险；需要辅助触点/电流检测 |
| GPIO 写入抛异常 | 软件可捕获 | 是 | 主机 `relay.fault` 测试覆盖，不等同真实线圈故障 |

## 4. 判定

### 通过

- 断开 IN/线圈后，泵在安全时间内停止；
- 没有出现泵继续运行但无人知晓的情况；
- 设备最终回到安全状态，且能明确报告“没有反馈”。

### 失败/缺口

- 泵已停但 API 仍显示 `pump=true` 直到 `max_run_s`；
- 触点粘连时无法得知泵仍在运行；
- 需要增加：
  - 继电器辅助触点接 GPIO 输入；
  - 或泵电流传感器/霍尔传感器；
  - 或独立硬件看门狗/急停回路。

## 5. 恢复

1. 断电；
2. 恢复继电器 IN/线圈接线；
3. 万用表确认 IN 空闲为低、触点释放；
4. 重新上电；
5. 复位设备后，确认 `pump=false`、`alarm=null`；
6. 再按正常流程做一次短泵测试。
