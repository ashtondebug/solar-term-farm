# TJC UART 协议（已核实部分 + 待实现设计）

> 本文件只记录已从官方 Wiki 核实的内容。命令语法、变量名与波特率尚未逐页确认，不能凭经验补全。

## 1. 已核实

- 设备返回数据以 `0xFF 0xFF 0xFF` 三个字节结束。
- `bkcmd` 系统变量控制是否返回指令成功/失败通知；上电默认值为 `2`，即只返回出错结果。
- 返回码（目录页列出，具体语义待逐页阅读）：
  - `00` 无效指令、`01` 成功、`02` 控件 ID 无效、`03` 页面 ID 无效、`04` 图片 ID 无效、`05` 字库 ID 无效、`06` 文件操作失败、`09` CRC 失败、`11` 波特率无效、`12` 曲线 ID/通道无效、`1A` 变量名无效、`1B` 变量运算无效、`1C` 赋值失败、`1D` 掉电存储失败、`1E` 参数数量无效、`1F` IO 失败、`20` 转义错误、`23` 变量名太长。
  - `0x24` 缓冲区溢出、`0x65` 控件点击、`0x66` 当前页面 ID、`0x67` 触摸坐标、`0x68` 睡眠触摸、`0x70` 字符串变量、`0x71` 数值变量、`0x86` 自动休眠、`0x87` 自动唤醒、`0x88` 启动成功、`0x89` SD 升级开始、`0xFD` 透传完成、`0xFE` 透传就绪。

## 2. 待核实

- 波特率、校验位、停止位；屏幕供电电压与 TTL 电平。
- 指令的完整语法（页面切换、文本赋值、数值赋值、触摸事件使能/返回）。
- 变量命名规则、字符串转义、中文字库与字体 ID。
- `bkcmd` 的推荐设置与主动解析模式。
- 屏幕进入/退出睡眠、RTC、亮度等系统变量。

## 3. 计划实现（尚未编码）

`ESP/display/tjc_protocol.py` 计划提供：

- `FrameParser.feed(bytes) -> list[Frame]`：按 `FF FF FF` 切帧；限制最大帧长，防止缓冲区无限增长。
- `Frame`：`kind`（ack/click/page/touch/string/number/boot）、`payload`、`raw`。
- `encode_command(...)`：在确认官方语法后实现；**当前不写死任何命令字符串**。
- `TjcLink`：UART 读写、断线重连、发送队列；不阻塞主循环。
- `Pages.sync(state)`：仅在值变化时发送，避免刷屏与串口拥塞。

## 4. 设计约束

- 屏幕只展示状态、提交意图；不得自行判断灌溉或直接驱动继电器。
- ESP32 的调试日志不能写到与屏幕共用的 UART；日志走 USB REPL/日志环。
- 任何未知返回码只记录、不崩溃；不把未知帧当成有效数据。
- 屏幕断线不能影响传感器、自动灌溉和 Web。
- 触摸事件必须经过设备端 `IrrigationController` 的安全校验。
